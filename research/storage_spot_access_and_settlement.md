# 西班牙独立储能参与现货市场与结算接口（ES-SP-04）

> 研究对象：西班牙大陆竞价区、独立（不与发电或需求设施绑定）的非水电化学储能。  
> 历史期：2025-01-01—2025-12-31；规则基准日：2026-08-11。  
> 本阶段只研究现货市场准入、主体/单位配置、计划、计量和结算接口；日前—日内套利（ES-SP-05）及现货—调频耦合（ES-SP-06）不在本文件内。

## 1. 先看结论

截至规则基准日，西班牙规则已经给独立储能设置了明确的市场入口和双向计划结构，但“完成市场主体注册”不等于某个项目已经完成并网、计量、系统信息、BRP 和代表配置。可确认的最简链条是：

```text
储能持有人/代表
  ├─ OMIE：市场主体（PM/agent）与销售/购买 UO
  └─ REE：系统主体、送出 UP 与取电 UP、UF、程序和计量
       └─ BRP：每个 UP 归属于一个 BRP，承担偏差和结算责任
```

对独立非水储能，P.O.3.1 Annex II 的直接规则是：送出（放电）和取电（充电）使用不同的 UP；按“BRP + 市场参与者”分别形成送出 UP 和取电 UP，UP 下再挂接储能设施对应的物理单元 UF。OMIE 的市场规则则要求销售 UO/购买 UO 与 REE 的 UP 协调建立并保持双向关联。上述结构是规则事实，不代表储能可以用一个“净功率”字段替代两个方向的计划和计量。[ES04-SP-UNIT-001][ES04-SP-UNIT-002]

现货交易的资金结算也分两层：OMIE 对日前/日内成交的买卖电量做市场结算；REE/OS 按计划、实际计量、偏差和系统过程做系统运营结算。OMIE 保证金和 REE/OS 的付款保证金是不同的规则入口；具体金额、网络费、税费和代表服务费不能从公开规则推导成一个统一的储能费率。[ES04-SP-SET-001][ES04-SP-SET-002]

## 2. 研究边界和证据规则

### 2.1 本阶段包含

- 储能设施持有人成为 OMIE 市场主体的条件；
- PM、市场代表、UO、UP、UF 和 BRP 的关系；
- 充电/取电和放电/送出的销售、购买方向；
- OMIE 成交结果进入 REE 计划和最终可执行计划的接口；
- 双向计量、偏差责任、市场结算、系统结算和保证金入口；
- 2025 年版本边界及储能专用尚未闭合事项。

### 2.2 本阶段不包含

本文件不判断日前—日内价差是否构成套利，不提出报价策略、收益率或循环策略，也不判断现货成交与 aFRR/mFRR/RR 预留、激活、补能之间的联合可行性；后两项分别进入 ES-SP-05 和 ES-SP-06。辅助服务规则只在解释 BRP/计量接口时作为交叉边界引用。

### 2.3 证据标记

- **F（规则事实）**：官方法规、BOE、CNMC 或 REE/OMIE 文件直接支持；
- **I（研究解释）**：对规则接口的整理，不增加规则要求；
- **A（建模假设）**：本阶段不新增；若未来模型需要，必须单独登记；

## 3. 市场主体和准入条件

### 3.1 储能持有人可以成为 OMIE 市场主体

**规则事实（F）：** 2025 年市场规则 Rule 4.1 明确列出“储能设施持有人”（titulares de instalaciones de almacenamiento）和代表为可成为日前/日内市场 agent 的主体类型。Rule 4.2 要求市场主体满足以下条件：

1. 储能设施有效登记在生产设施行政登记中，或代表能够证明其代表资格；
2. 取得电力系统主体（sujeto del sistema）资格；
3. 签署日前/日内市场规则和结算条件的加入合同；
4. 向 OMIE 提交唯一有效 NIF 对应的 agent code；
5. 提交有效 ACER code，用于 REMIT 识别和报告；
6. 提交银行账户用于资金收付。

OMIE 在文件齐备且条件满足后，规则给出两个工作日内完成系统登记、第三个工作日后可以参加相应市场和场次的流程。上述为市场 agent 层的准入条件，不替代 REE 的系统主体、UP/UF、并网和计量手续。[ES04-SP-ACCESS-001]

**研究解释（I）：** 独立储能不需要先被写成传统发电商或消费者才能取得 OMIE 市场主体类别；但其交易只能挂在已被 OMIE 和 REE 同步识别的 UO/UP 结构上。

### 3.2 系统主体、UP 建立和项目注册边界

**规则事实（F）：** P.O.3.1 规定，PM 向 OS 申请 UP 的新建、变更和注销，并向 OS 提交市场成交结果在多 UP 情形下的 UP 级申报、UF 分解、不可用信息和偏差信息。UP 的代码由 OS 按系统程序批准，每个 UP 和 UF 具有 EIC 代码。[ES04-SP-ACCESS-002]

P.O.14.8 将“安装”定义为生产或储能安装，并以 RAIPEE（生产设施登记）或适用的行政登记识别；新安装的临时高与其计量边界点由读表责任主体通知，之后再按行政登记信息更新。新主体可向 OS 申请成为 sujeto de liquidación，并须提交必要文件和付款保证金。[ES04-SP-SET-002]

**待确认（U）：** 公开规则确认“有效登记”和 OS/OMIE 的主体流程，但没有为每一个独立储能项目列出一份统一的项目级清单，尚不能仅凭这些条文判断以下具体事项：

- 项目应采用何种 RAIPEE 登记类别、何时取得该登记；
- 并网许可、接入合同、CIL、边界点和读表责任主体之间的项目文件交叉表；
- 某一项目向 REE 申请 UP 时使用的最新电子表单和数据交换版本；
- 申请市场 agent、系统主体、BRP 和代表是否可由同一法人一次性办理。

因此，“储能可以成为市场主体”是 **F**；“某项目已经完成现货准入”在没有项目文件和 OS/OMIE 确认前是 **U**。[ES04-SP-ACCESS-003]

## 4. PM、代表、UO、UP、UF 和 BRP 的关系

### 4.1 各个单位的作用

| 缩写 | 西班牙语 | 本文件中的作用 |
|---|---|---|
| PM | Participante en el Mercado | 对市场和系统提交交易、计划、UF 分解等信息的市场参与者；可为储能持有人或代表 |
| UO | Unidad de Oferta | OMIE 接收报价和执行市场结算的销售或购买报价单位 |
| UP | Unidad de Programación | REE 建立能源计划、技术校核和偏差接口的基本单位 |
| UF | Unidad Física | UP 下代表具体储能设施和电气位置的物理单元 |
| BRP | Sujeto de Liquidación Responsable del Balance | 对其 UP 的偏差承担财务责任并参与系统结算的主体 |
| 代表 | Representante | 可直接或间接代表持有人参与市场和收付款；代表不自动等于 BRP，除非按规则承担/接受 BRP 责任 |

上述定义和职责来自 P.O.14.1/P.O.14.8、P.O.3.1 Annex II 及 OMIE Rule 4/12。[ES04-SP-ROLE-001]

### 4.2 独立非水储能的送出/取电 UP

**规则事实（F）：** P.O.3.1 Annex II §2.3(b) 对“未与发电或需求关联的非水储能”规定：

- 送出电能和取用电能使用**不同的 UP**；
- 对每个“BRP + 市场参与者”组合，形成一条送出 UP；
- 对同一“BRP + 市场参与者”组合，另形成一条取电 UP；
- 每条 UP 由该组合下各储能设施对应的、具有明确电气位置的 UF 组成；
- 对最大功率不低于 100 MW 或对系统安全具有重要性的设施，OS 或与 OS 协调的配电网运营方可以按节点要求增设特定 UP。

可以用下图理解一座独立储能项目的常规规则结构：

```text
放电/送出方向：  储能 UF(s) → 送出 UP（按该方向的 PM + BRP 组合）→ 销售 UO → OMIE
充电/取电方向：  储能 UF(s) → 取电 UP（按该方向的 PM + BRP 组合）→ 购买 UO → OMIE
```

这是便于理解的常见示意，不是要求两个方向必须使用同一个 BRP；规则要求的是每个方向按相应的 PM+BRP 组合建立 UP，具体项目的 BRP 组合仍需确认。[ES04-SP-UNIT-001]

这里的“送出/取电”是系统计划和物理计量方向；它不等同于已经确定的报价价格或收益。[ES04-SP-UNIT-001]

### 4.3 UO 与 UP 的市场关联

**规则事实（F）：** 在 OMIE 的市场注册关联层，Rule 12 要求 UO 的建立与 OS 的 UP 建立协调进行；对一个 market agent，不能存在没有对应 UP 的 UO，也不能存在没有对应 UO 的 UP，且 UO 保持销售或购买方向。P.O.3.1 的计划执行层则允许代表/PM 的一个市场 UO 包含多个 UP，并要求成交结果按 UP 申报、再分解至 UF；这不是否定 Rule 12 的注册关联，而是不同层级的聚合/分解关系。UO 的最大功率由所关联 UF 的申报最大功率汇总并受行政登记/许可信息约束。[ES04-SP-UNIT-002][ES04-SP-ROLE-002]

因此，对独立储能，放电方向对应销售 UO，充电方向对应购买 UO；同一储能项目的两个方向不能仅用一个“正负号可变”的单一 UO 来替代规则所要求的方向单位。

**代表聚合的边界（F/U）：** 代表以自己名义、为第三方账户间接代表时，可在一条 UO 中聚合多个被代表方的计划；直接代表只能把一个被代表方纳入相应 UO。P.O.3.1 又规定，直接代表应使用储能持有人的 UP，间接代表对功率超过 1 MW 的设施可以使用代表自己的 UP 或持有人的 UP；若代表管理的是单一聚合 UF，则只能使用代表自己的 UP。[ES04-SP-ROLE-002]

这意味着“每个项目一套 UO/UP”不是所有代表模式下的唯一商业配置；对具体项目，代表模式、BRP 组合和跨项目聚合仍需在 OS/OMIE 账户层确认（U）。

### 4.4 BRP 和代表模式

**规则事实（F）：** 所有市场参与者须对偏差承担财务责任，或者通过合同将责任交给自己选择的 BRP；每个 UP 在任一时点只归属于一个 BRP。[ES04-SP-ROLE-003]

P.O.14.1 对代表模式的资金责任区分如下：

| 模式 | 代表关系 | 市场/系统结算的直接责任 | 保证金主体 |
|---|---|---|---|
| 直接代表 | 代表以被代表方名义、为被代表方账户行动 | 被代表储能持有人是收款/付款主体 | 被代表储能持有人 |
| 间接代表 | 代表以自己名义、为被代表方账户行动 | 代表承担对外付款/收款关系；内部再按合同结算 | 代表 |
| 持有人直接参与 | 持有人自己作为 PM/市场主体 | 持有人 | 持有人 |

对不属于调节区的独立储能，BRP 可以是间接代表、出售电量的商业化主体，或另行指定的 BRP；同一 UP 不应同时分配给多个 BRP。P.O.14.8 还规定，变更 sujeito de liquidación 一般需要提前至少 15 个自然日通知，且旧主体在生效日前仍承担相应财务责任。[ES04-SP-ROLE-003][ES04-SP-SET-002]

**研究解释（I）：** 市场主体、代表和 BRP 是三个相互关联但不必由同一法人承担的角色。储能项目在商业上可以“持有人 + 交易代表 + BRP”，也可以由一个主体承担多个角色；是否允许某种具体组合，取决于市场/系统登记和合同文件，而不是仅由电池的技术参数决定。

## 5. 现货交易方向和计划进入 REE 的流程

### 5.1 充电和放电的报价方向

**规则事实（F）：** OMIE 市场规则把报价分成销售和购买，分别由销售 UO 和购买 UO 提交。对独立储能：

- 放电时，储能向系统送出电能，对应销售方向；
- 充电时，储能从系统取电，对应购买方向；
- 两个方向各自受其 UP、UF 最大功率、系统限制、市场报价验证和保证金验证约束；
- 同一交付时段可以有一个方向的成交计划，能否在同一时段同时出现净送出和净取电，不由“电池允许双向”自动推出，必须符合 UO/UP 和计划校核。

最后一项是对单位结构的研究解释，不是额外禁止规则。市场规则只规定销售/购买单位必须保持相应的最终头寸；储能能量状态和同一时段的内部控制逻辑需由项目的 UP/UF 配置和运行数据确认。[ES04-SP-UNIT-001][ES04-SP-UNIT-002]

### 5.2 日前成交到 REE 计划

**规则事实（F）：** 2025 适用的系统程序大致按以下顺序运行：

```text
OMIE 日前成交结果（PDBC/市场结果）
      ↓  在 UO 含多个 UP 时，由 PM 按 UP 提交必要的计划申报
PDBF（基础运行计划）
      ↓  系统安全/技术约束处理
PDVP（临时可行计划）
      ↓  系统运营商确认
PDVD（最终可行的日前计划）
      ↓  后续日内成交/系统程序
PHF / PHFC（最终计划）
      ↓
P48 与实际计量/偏差结算接口
```

P.O.3.1 要求 PM 负责：向 OS 申请 UP 的高/变更/注销；在 UO 包含多个 UP 时对日前和日内市场结果按 UP 进行申报；将 UP 计划分解至 UF；报告不可用和偏差。OMIE 将市场结果、价格和相关交换信息发送给 OS，OS 形成 PDBF，进行技术可行性处理并确认 PDVP 为 PDVD；日内市场以 PDVD 作为相应基础（`S-SP-BOE-2025-RULES` Rules 35–36、58.4）。[ES04-SP-PLAN-001]

### 5.3 日内成交和 PHF/PHFC 更新

日内市场的详细订单参数在 ES-SP-03，但其对储能的计划接口属于本阶段的结算边界：

- 日内拍卖结果到达后，若 UO 由多个 UP 组成，PM 按 UP 进行相应申报和 UF 分解；
- 连续日内交易结果到达后，PM 仍须按 UP 提交程序信息，OS 再形成 PHFC；
- 如果 UO 与 UP 是直接一一对应，则不需要为了“拆分多个 UP”额外做项目级分摊；如果代表聚合多个 UP，则需要完成规则要求的 UP 级申报和 UF 级分解；
- 计划的具体消息名、字段、版本号、修订标志和发布时点需由 ES-SP-07 数据阶段锁定。

2025 年 P.O.3.1 已将日前/日内程序与四分之一小时计划接口统一，但规则版本在 2025 年内有切换，不能将 2025 全年按一个文件版本直接回填。[ES04-SP-PLAN-002]

## 6. 双向计量、实际执行和偏差

### 6.1 储能必须区分送出和取电计量

**规则事实（F）：** P.O.14.1 对“其他储能”规定，UP 的计量值由其所含储能设施的边界点计量汇总。2025 年 P.O.10.5/相关计量程序对储能同时记录 Activa Saliente（有功送出/出口）和 Activa Entrante（有功取入/进口），而不是只保留一个净有功值。缺失或无效计量不能笼统概括为“双向均直接用计划值替代”：短时缺口按相应历史/插值等方法估算；对较长缺口，储能边界的方向性规则可将送出估为 0、取入按最大取入功率估算，具体适用还取决于边界类型和程序版本（`S-MITECO-2025-ISP` P.O.10.5 §§4.4.1–4.4.3）。[ES04-SP-METER-001][ES04-SP-METER-002]

### 6.2 2025 年 15 分钟计量边界

MITECO 2025-03-28 决议（BOE-A-2025-6693）自 2025-05-01 起实施相关 P.O.10.x 变更。公开文本将四分之一小时计量、小时计量和缺失数据处理纳入“最佳能源值”程序；对缺失或无效数据，读表责任主体按相应规则估算或补发。该程序解决的是时间分辨率和计量形成，不等于允许储能项目没有合格的双向计量设备。[ES04-SP-METER-002]

**待确认（U）：** 对独立储能项目，仍需从 OS/读表责任主体取得：

- 边界点具体计量类别、主/备用表和双向寄存器映射；
- Activa Saliente/Entrante 与送出 UP/取电 UP 的字段交叉表；
- 缺失、更正、估算和重发布的项目级标记；
- 2025 年 1—4 月和 5 月以后计量分辨率切换在具体项目历史文件中的实际版本。

### 6.3 计划与实际值的偏差责任

**规则事实（F）：** BRP 对其 UP 的偏差承担财务责任。对储能来说，放电 UP 的实际送出、充电 UP 的实际取电、相应的计划值以及系统/市场调整结果共同构成偏差和后续结算输入。储能不能只把“电池 SOC 变化”作为公开市场结算的唯一测量变量；SOC 不是 P.O.14.1 公开定义的计量替代字段。[ES04-SP-ROLE-003][ES04-SP-METER-001]

**研究解释（I）：** 这也是为什么独立储能的现货收入测算至少要把“成交计划、最终计划、送出计量、取电计量和 BRP 偏差”分开保存。具体偏差价格、单价/双价适用、修订和系统服务结算属于平衡/不平衡阶段，不在本文件重复计算。

## 7. 结算、保证金和费用接口

### 7.1 OMIE 现货市场结算

**规则事实（F）：** OMIE Rule 34 对日前市场按每个销售/购买 UO 和交易时段建立结算记录；正价格时，售电方获得收款、购电方付款；负价格时，方向相反。金额按成交功率 × 交易时段小时数 × 区域边际价格计算。日内拍卖/连续市场也按成交 UO、时段、价格和时段长度形成相应的收付款记录。[ES04-SP-SET-001]

对独立储能的直接含义是：

- 送出 UO 的现货结算是销售方向；
- 取电 UO 的现货结算是购买方向；
- 负价下购买可能形成收款、销售可能形成付款，但这只是 OMIE 市场层的方向结算；
- 该结算不自动扣除电池效率损失、衰减、代表费、网络费用、税费、BRP 偏差或其他合同项。

### 7.2 REE/OS 结算和付款保证金

**规则事实（F）：** P.O.14.1 的对象包括 OS 结算、收付款通知、付款保证金、账户登记和发票/收付。其适用于 PM、BRP、BSP 和 OS，并与 P.O.14.2（市场参与者准入）、P.O.14.3（付款保证金）、P.O.14.7（发票/收付款）和 P.O.14.8（设施结算主体）相互衔接。[ES04-SP-SET-002]

代表模式决定对外责任：直接代表由被代表主体承担相应收付款和保证金；间接代表由代表承担对外付款/收款和保证金责任。BRP 还对偏差承担财务责任，因此“OMIE 保证金”“REE/OS 付款保证金”“BRP 偏差成本”不能合并为一个统称的储能保证金。[ES04-SP-ROLE-003][ES04-SP-SET-002]

### 7.3 费用和金额的边界

截至基准日，公开规则支持以下判断：

| 项目 | 当前状态 |
|---|---|
| OMIE 市场结算 | 规则事实：按销售/购买 UO、价格、功率和时段长度结算 |
| OMIE 交易保证金 | 规则事实：市场主体须按市场规则维持适用保证金；不足可导致报价/单位暂停或清算后果 |
| REE/OS 付款保证金 | 规则事实：由 P.O.14.1/P.O.14.3 等系统结算程序管理 |
| BRP 偏差成本 | 规则事实：BRP 对偏差承担财务责任；具体价格和计算留不平衡结算阶段 |
| 网络费、税费 | U：取决于项目接入、计量、税务和适用法律，不能用 OMIE 现货规则单独确定 |
| 代表服务费 | U：通常来自商业合同，公开市场规则未给出储能统一费率 |
| 储能专用现货结算费率/优惠 | U：本阶段未找到一项适用于所有独立储能的统一专用费率 |

### 7.4 暂不纳入的技术经济参数

规则没有在本阶段为独立储能现货结算统一给出 SOC 下限/上限、充放电效率、循环寿命、可持续时长、补能时长或最低能量容量。将这些参数写入现货收益模型属于 **A**，必须由主线程另行批准，不能从 UO/UP 规则推导。

## 9. 规则事实、研究解释、假设和待确认事项分离

### 9.1 已确认的规则事实（F）

1. 储能设施持有人是 OMIE 日前/日内市场主体类别；市场 agent 需满足登记、系统主体、加入合同、NIF、ACER 和银行账户条件。
2. 非水独立储能送出和取电使用不同 UP；每个方向按 BRP 和 PM 形成 UP，UP 下挂接 UF。
3. OMIE 销售 UO/购买 UO 与 REE UP 建立协调关联；UO 只能维持对应销售或购买头寸。
4. PM 负责必要的 UP 申报、UF 分解、不可用和偏差信息，REE 负责计划和系统技术处理。
5. BRP 对偏差承担财务责任，每个 UP 在同一时点归属于一个 BRP；直接/间接代表的付款和保证金责任不同。
6. 储能送出和取电的边界计量分别处理，不能只用一个净计量值替代。
7. OMIE 现货收付款、REE/OS 系统结算和 BRP 偏差结算是相互衔接但不同的结算层。

### 9.2 研究解释（I）

- 对独立储能而言，放电销售 UO/送出 UP 和充电购买 UO/取电 UP 是最清晰的规则映射；实际代表聚合可能形成更复杂的 UO/UP 账户结构。
- “成交”只能证明市场层的经济计划和收付款记录，不能单独证明储能已获得物理执行、计量合格或不会产生 BRP 偏差。
- 现货收益测算必须同时保存 OMIE 成交和 REE 最终计划/计量，不能只使用价格序列和成交量。

### 9.3 建模假设（A）

本阶段没有新增建模假设。若未来将单项目简化成一条送出 UP 和一条取电 UP、采用固定效率/SOC/持续时长或将费用合并为一个参数，均需在模型阶段显式记录为 A，而不是西班牙规则。

### 9.4 待确认（U）

- 单个独立储能项目的 RAIPEE、系统主体、CIL、计量点、UP/UF 和 EIC 的完整注册/数据交叉表；
- 代表间接聚合多个储能设施时，OMIE UO、REE UP、BRP 和计量聚合的实际账户配置；
- 2025 年每日 P.O.3.1/P.O.9.2/P.O.14.1/P.O.14.4 版本、REE 生产切换日和消息字段；
- 2025 年双向计量缺失、估算、修订和重发布标记；
- 具体 OMIE/OS 保证金金额、网络费、税费和代表合同费；
- 储能现货计划与辅助服务预留、激活和补能之间的联合接口（转 ES-SP-06）。
