# 西班牙 2024 aFRR 历史可比性与 680/681 时间表示审计

审计日期：2026-09-17（Asia/Shanghai）  
范围：2024-07 至 2024-11 已保存的 eSIOS 原始 JSON；重点是指标 680/681（aFRR/二次调节激活能量）与 632/633（上/下 aFRR 备用分配）。  
本轮只读检查本地原始文件和已登记的官方资料，未新增认证 API 请求，也未在 `data/raw/ES/` 新建或覆盖文件。

## 1. 结论

1. **680/681 的 MWh 单位尚未证据闭合。** eSIOS 返回的 `magnitud` 仅为 `Energía`（id 13），没有在指标响应中给出 MWh/kWh 字符串；`tiempo` 仍为 `Hora`（id 4）。REE 的 SRS 技术指南说明了二次调节能量结算和 15 分钟汇总，但当前证据没有把公开指标 ID 680/681 直接交叉映射到该结算变量。因此不得把 680/681 数值确定标作 MWh，也不得从名称或数值量级推断单位。
2. **680/681 的实际记录粒度不是 `step_type` 或 `tiempo` 单字段可以决定的。** 2024-07/08 全部为 60 分钟记录；2024-11 同一响应元数据仍为 `step_type=step`、`tiempo=Hora`，但在 `2024-11-19T23:15:00Z` 出现 15 分钟记录。eSIOS API 文档列出 `step_type`、`datetime_utc` 和 `time_trunc` 字段，但未定义 `step` 的保持、插值或前向填充语义。不能据此前向填充缺点。
3. **2024-11-20 是可观察的数据/系统断点候选，不是西班牙接入 PICASSO 的日期。** 现有原始序列在 UTC `2024-11-19T23:00:00Z` 后从小时记录转为 15 分钟记录，首个非整点季度记录为 `2024-11-19T23:15:00Z`；当地 2024-11-20 00:00（对应 UTC `2024-11-19T23:00:00Z`）也是该新段的整点季度起点。主线程日计数核验显示 11/20–11/30 通常每天 96 条，11/27 为 88 条，仍不应视为无缺口。REE 官方材料说明 SRS 在 2024-11-19 实施；REE 当前平台页把 MARI 列为 2024-12、PICASSO 列为 2025-06，ENTSO-E 的 PICASSO 页面记载 Red Eléctrica 于 2025-06-19 接入。因此 2024-11-20 只能标为 **SRS/接口粒度经验断点**，不能标为 PICASSO 接入断点。
4. **632/633 与 680/681 方向上可以配对，物理量上不能直接视为同一量。** 632 是上调备用分配、633 是下调备用分配；响应元数据为 `magnitud=Potencia`、`tiempo=Quince minutos`。CNMC/BOE P.O.7.2 的官方规则分别规定上/下备用容量和能量报价，备用容量的规则量纲为 MW。680/681 则是上/下激活能量的 API 指标名称。只有在 680/681 单位和每条记录所代表的时长被另外确认后，才可能在 QH 窗口内研究 `680/(632×0.25 h)` 和 `681/(633×0.25 h)`；小时记录、缺失区间和非连续记录不得这样换算。该比值仍不是“本站激活”或实际激活率。
5. **2024-07 至 2024-11 不应合并为一个同质样本。** 680/681 在 9、10 月存在长间隔缺失；11 月同时出现 15、60、135 分钟间隔。632/633 始终为显式 15 分钟记录，但 10 月有 2,980 点，不能以固定月点数替代实际覆盖。所有缺失和粒度切换应保留为数据质量状态，不得用插值或剪裁修复。

## 4. 分层判断

### 4.1 规则事实

- CNMC/BOE 2024 修订的 P.O.7.2 将二次调节备用容量和能量报价分开，并分别设置上调、下调结构；备用容量的规则量纲为 MW，能量报价量纲为 €/MWh。该规则事实支持 632/633 作为上、下备用分配量的方向区分，但不把它们变成激活量。
- REE 官方平台状态页给出的西班牙欧洲平衡平台接入月份为 MARI 2024-12、PICASSO 2025-06。ENTSO-E 官方 PICASSO 页面给出 Red Eléctrica accession 的具体日期 2025-06-19。
- REE/eSIOS 官方 SRS 材料将 SRS 的成功实施定位在 2024-11-19。由此可以解释为什么 2024-11-20 附近值得作为数据接口/系统版本边界审计，但不能改写为 PICASSO 接入。
- eSIOS API 响应本身确认了指标名称、方向、`magnitud`、`tiempo`、`step_type`、UTC 时间戳和地理区域；它没有确认 680/681 的 SI 单位、数值是否已按 QH 聚合、缺点保持规则或修订终态规则。

### 4.2 研究解释

- 680/681 在 2024-07/08 小时粒度、2024-11 晚间出现 QH 粒度，与 SRS 2024-11-19 实施相邻，**可能**反映 SRS/接口版本变化。但这是时间相关性，不足以单独证明因果或证明每个缺口可前向填充。
- 680/681 与 632/633 可以按同方向做候选量纲审计。若未来官方字段交叉表确认 680/681 每条 QH 值为 MWh，且记录连续，则 `energy/(MW×0.25 h)` 是无量纲的 QH 强度；在小时或混合粒度中不能套用同一公式。若另行研究 `E/R`（E 为 MWh、R 为 MW），结果才具有小时量纲，且仍须先确认单位、时长和记录连续性。
- `step_type=step` 只能作为接口字段保留，不能在模型或统计脚本中当作缺失值填补指令。任何补值必须有官方 step 语义和前置锚点，并单独记录。

### 4.3 待确认问题

1. 680/681 是否明确为 MWh、kWh 或其他能量单位，以及一个值代表小时能量、QH 能量还是接口展示转换。
2. 680/681 与 REE SRS 结算变量（包括上/下能量结算变量）的官方指标 ID 交叉表。
3. eSIOS `step_type=step` 的官方保持、插值、缺失和修订语义；当前无依据做 forward-fill。
4. 2024-11-19/20 的 680/681 粒度转换是否是 SRS 实施直接结果，还是数据发布/历史重算接口变化；2024-11-20 不是已确认 PICASSO 接入日。
5. 680/681 数值正负号是否代表方向，还是方向已编码在指标 ID 中；名称 `subir`/`bajar` 不能单独闭合数值符号规则。
6. 2024-09/10 长间隔和 2024-11 的 135 分钟间隔是业务无记录、发布缺口、权限/历史保留限制还是后续修订造成；现有响应无法区分。

## 5. 给主线程的使用边界

- 历史统计应至少把 2024-07/08 的 680/681 小时段、2024-09/10 的缺失段、2024-11-20 附近的经验粒度断点分开标记。不得把 2024-11-20 命名为 PICASSO 上线。
- 632/633 可作为上、下备用分配功率的独立序列。680/681 可作为方向性激活能量候选序列，但在单位闭合前应保留 `energy_unit_unconfirmed` 状态。
- 不得以 680/681 的 `step` 生成缺失点，不得把 632/633 当作实际激活，不得将 `680/(632×0.25)` 或 `681/(633×0.25)` 写成已校准的激活率/本站 alpha。
- 若后续要闭合单位或补取缺失，应只在取得新的官方字段交叉表、版本说明或明确的 API 响应证据后另建不可覆盖的 raw 批次；本报告不授权任何补值或生产实现。
