# 西班牙 aFRR 固定订单双顺序诊断（合成验证）

状态：**合成候选路径验证，不是历史激活映射，也不是可执行交易结果。**

本模块把同一组固定输入分别按两种顺序积分：

1. 上调后下调（`up_then_down`）；
2. 下调后上调（`down_then_up`）。

两种顺序使用完全相同的基线功率 `P`、上调容量 `R_up`、下调容量 `R_down`、`a_up`、`a_down` 和初始 SOC。顺序不是优化变量，不赋概率，也不挑选收益较高者。

## 输入口径

- 一个季度小时固定为 15 分钟；`P` 为交流侧基线功率，送电／放电为正，购电／充电为负。
- `R_up`、`R_down` 是固定备用头寸，单位 MW，必须非负。即使某个 `a` 为 0，承诺的备用头寸仍单独检查。
- `a_up`、`a_down` 是外生的无量纲激活强度。满幅持续时间分别为 `15 × a_up` 分钟和 `15 × a_down` 分钟；剩余时间保持基线 `P`。
- 每个季度小时强制满足 `0 ≤ a_up ≤ 1`、`0 ≤ a_down ≤ 1`、`a_up + a_down ≤ 1`。不做裁剪、归一化或缺失值填补；非法输入直接拒绝。
- 上调实际功率为 `P + R_up`，下调实际功率为 `P − R_down`，无激活实际功率为 `P`。下调后的实际功率仍可能为正，例如 `P=50, R_down=20` 时仍放电 30 MW；也可能穿过零点变成充电。
- 默认电池参数为：功率上下限 100 MW，SOC 安全区间 10–190 MWh，充放电效率均为 0.92。

## 计算口径

对每个子段直接使用合成后的实际功率：

```text
实际功率 ≥ 0：SOC变化 = −实际功率 × 时长 / η放电
实际功率 < 0：SOC变化 = −实际功率 × 时长 × η充电
```

DC 吞吐量也按实际功率符号计算：

```text
放电吞吐 = 实际功率 × 时长 / η放电
充电吞吐 = −实际功率 × 时长 × η充电
```

SOC 超过 10–190 MWh 时保留原始轨迹，绝不截断。报告区分：

- `first_boundary_contact_minute`：原始连续轨迹首次到达 10 或 190 MWh 的时刻；
- `violation_onset_boundary_minute`：首次从可行区经边界进入严格不可行区的 boundary crossing 时刻。轨迹恰好停在 10 或 190 MWh 不构成违规；若之后继续越界，违规从该 crossing 之后开始。`1e-9` 仅是物理残差判断容差，不是 SOC 裁剪或输入归一化。

功率可行性检查所有实际子段是否在 `[-100, +100]` MW 内；备用头寸可行性独立检查：

```text
P + R_up ≤ 100 MW
P − R_down ≥ −100 MW
```

同时检查基线自身是否在功率区间内。功率或备用头寸不合格时仍输出完整原始轨迹，不改变订单。

## 固定输入不变量

在基线、上下调容量、激活强度和效率均保持不变时，只改变上下调子段的先后顺序，不改变总末端 SOC 和总 DC 吞吐量；顺序可能改变中间 SOC 路径及是否触及安全边界。这个结论只适用于本合成假设，不外推到真实秒级指令、变化基线、限幅控制、退化或重新优化。

## 运行与输出

从项目根目录运行：

```powershell
python -m src.es_milp_sandbox.order_diagnostic
```

也可指定输出路径：

```powershell
python -m src.es_milp_sandbox.order_diagnostic --output outputs/es_milp_sandbox/order_diagnostic_results.json
```

默认结果文件为：[order_diagnostic_results.json](../outputs/es_milp_sandbox/order_diagnostic_results.json)。结果由模块演示输入实时生成，不是手写固定数值。

## 典型合成锚点

`P=0, R_up=R_down=20 MW, a_up=0.2, a_down=0.4` 时，上调持续 3 分钟，下调持续 6 分钟，剩余 6 分钟无激活：

- `E0=11 MWh`：上调先行在 2.76 分钟到达 10 MWh，之后越界；下调先行不触碰下界；两者末端约 11.753043 MWh。
- `E0=189 MWh`：下调先行在 3.260869565 分钟到达 190 MWh，之后越界；上调先行保持可行。
- `P=50, R_down=20 MW`：下调阶段实际仍为 30 MW 放电，不能把下调容量直接当作充电。
- `P=10, R_down=30 MW`：下调阶段实际为 −20 MW，按充电效率计算，不能按放电处理。

## 边界与门禁

该模块不读取价格、REE／OMIE 文件、API key 或历史激活，不产生收益，也不关闭历史数据门禁。它只验证已确认的固定订单路径和电池物理计算；完整历史 aFRR 场景仍需通过数据单位、时间含义和本站映射验收后，才能进入 MILP 重优化。
